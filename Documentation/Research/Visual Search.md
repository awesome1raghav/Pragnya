# Visual search in NEXTRON

As of 26 November 2026. The `/sources` page accepts a JPEG, PNG or WebP image or video screenshot, an optional crop, and an image URL. **Local** results search indexed images in the selected case. **Web** results use SerpApi's Google Lens endpoint only after the operator selects Web and consents to sending a derived search copy. Both are investigation leads, never proof of source, chronology or authenticity.

## Choice and alternatives

| Component | Choice | Reason |
|---|---|---|
| Image encoder | [SigLIP 2 Base/16, 224 px](https://huggingface.co/google/siglip2-base-patch16-224) at revision `75de2d55ec2d0b4efc50b3e9ad70dba96a7b2fa2` | Apache 2.0, 768-dimensional image representations, suitable for semantic similarity on the local CPU; actual retrieval accuracy on NEXTRON evidence remains to be benchmarked. |
| Alternative encoder | [CLIP](https://github.com/openai/CLIP), [DINOv2](https://huggingface.co/facebook/dinov2-small) | CLIP is mature; DINOv2 favors visual appearance and lacks the shared text/image space. Re-evaluate on a labelled NEXTRON set before claiming a winner. |
| Vector index | [Qdrant](https://qdrant.tech/documentation/) HNSW with cosine distance | Already planned as a rebuildable projection. Case payload filtering and local Docker deployment cost no per-query cloud fee. |
| Alternative index | [pgvector](https://github.com/pgvector/pgvector), [Milvus](https://milvus.io/docs/comparison.md), [Pinecone](https://www.pinecone.io/pricing/) | pgvector would avoid a service but changes the agreed PostgreSQL/projection boundary. Milvus adds operations. Pinecone is managed with recurring charges. Benchmark before switching. |
| Web lookup, opt-in | [SerpApi Google Lens](https://serpapi.com/google-lens-api) | Free plan allows [250 searches/month](https://serpapi.com/pricing), with an hourly limit. Uploads are [limited to 500 KB](https://serpapi.com/image-api). NEXTRON checks the account plan and remaining free searches before sending any image. |
| Alternative web lookup | [Google Cloud Vision Web Detection](https://docs.cloud.google.com/vision/docs/features-list) | It can return full, partial, page and visually similar matches from Google's covered web, but requires a billing account even in its free tier. |

Web search is configured only when `WEB_VISUAL_SEARCH_ENABLED=true` and `SERPAPI_API_KEY` is present in the backend environment. The key never reaches the browser. A URL input fetches that *specific URL* under NEX-SRC's SSRF rules; the derived image then goes to the selected search provider. Search results are not imported into the case automatically.

## Processing

1. Evidence is preserved write-once with SHA-256 by NEX-EVD. The separate worker reads an image, applies EXIF orientation, rejects large or unsupported rasters, and computes a normalized SigLIP 2 embedding. Versioned vectors are stored in PostgreSQL `visual_embeddings`.
2. The worker upserts deterministic evidence IDs into a Qdrant collection with a case filter. It retries after errors and replays PostgreSQL on restart and periodically. `python -m Scripts.Maintenance.RebuildVisualIndex` repairs the index manually. Original evidence is never modified.
3. The API decodes an uploaded query or an SSRF-checked URL, optionally crops it, computes an embedding and queries Qdrant with a mandatory case filter. It resolves returned IDs back against PostgreSQL in the same case. Similarity scores are cosine values, not calibrated probabilities.
4. For an explicitly requested web search, the API orients and crops the image, strips metadata, compresses a derived JPEG under 500 KB, checks that the SerpApi account is on the free plan with searches left, uploads the derived image, and requests Google Lens results. It returns validated HTTP(S) links without claiming that a provider's exact-match label is verified evidence. Each image result gets a short-lived preview token. NEXTRON fetches visible previews under the NEX-SRC public-address, redirect, timeout, byte and pixel limits, then serves a resized metadata-free copy to the browser. If a source blocks retrieval, the source link remains available.

## Setup and performance

Install the pinned `Backend[visual]` extra, then run `python -m Scripts.Maintenance.InstallVisualModel` once and `docker compose -f Infrastructure/Docker/docker-compose.yml up -d qdrant`. Set `QDRANT_URL=http://127.0.0.1:6333` in ignored `Backend/.env`; restart the API and worker. The model installer pins the revision and writes SHA-256 checksums; inference uses local files only. `GET /api/v1/visual-search/status` reports configuration. POST multipart to `/api/v1/cases/{case_id}/visual-search` with `file` or `url`, `top_k` (1–50), and optional JSON `crop` rectangle. The `/sources` page provides this form.

To turn on web lookup, set `WEB_VISUAL_SEARCH_ENABLED=true` and `SERPAPI_API_KEY=<your free-plan key>` in ignored `Backend/.env`, then restart only the API. A free key can be obtained from [SerpApi](https://serpapi.com/pricing). Search mode `web` also requires `allow_external=true` on every request. No paid-plan or depleted free-plan request is sent for image upload. The query image leaves this machine only for an explicit web search.

Batch embedding limits model overhead. Cache local evidence thumbnails from the existing preview route. Web previews use a 10-minute browser cache and a bounded server-side token registry; the browser never hotlinks arbitrary result images. Qdrant [recommends creating payload indexes before bulk uploads](https://qdrant.tech/documentation/tutorials/bulk-upload/) and supports [quantization](https://qdrant.tech/documentation/quantization/) to reduce memory. Enable quantization only after measuring recall on a labelled set. For frequent duplicate detection, existing cryptographic and perceptual hashes should rank exact and transformed copies ahead of semantic neighbors. Current implementation does not yet fuse those rankings or index video frames; screenshots can be queries, but the corpus contains preserved still images only.

## Verification and limits

On this development machine, the pinned model loaded and produced a 768-dimensional unit vector. PostgreSQL migration `0008` applied and Alembic reported no pending schema change. The worker indexed 38 real preserved images; the live status probe measured 38 PostgreSQL embeddings and 38 Qdrant points. A live FastAPI/Qdrant query of one of those images returned HTTP 200 and a self-match cosine score of 1.0. The full backend suite passed (262 tests, one Pillow warning), and the full browser suite passed (18 tests). The focused SerpApi, thumbnail and API tests passed (10 tests). A live SerpApi account check confirmed the Free Plan. Two explicit web requests using a generated image each returned HTTP 200 and five unverified web leads. Four of the second request's five results had preview tokens; two of the first three preview fetches returned HTTP 200 and one returned 404, which the UI handles with a source-link fallback. The account reported 248 free searches left after the checks. No private evidence was sent. These checks do not establish recall, latency at scale, or public-web coverage. Input files are limited to 10 MiB and 24 megapixels. Qdrant is an index that can be rebuilt from PostgreSQL.
